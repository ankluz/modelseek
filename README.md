# modelseek

<img src="frontend/favicon.svg" width="64" alt="">

Локальный поисковик 3D-моделей по нескольким сайтам сразу: свой интерфейс, прозрачное ранжирование, темы,
избранное, подписки на запросы, поиск по картинке через внешние сервисы.

**Источники:** Printables, MakerWorld, Thingiverse, Thangs, Cults3D, MyMiniFactory, свои источники с JSON API,
любые сайты через SearXNG и сайты-ссылки (Yeggi, GrabCAD, CGTrader…).

**Два профиля:** админский (http://127.0.0.1:8088, только с этого компьютера: всё, включая настройки) и
внешний на отдельном порту — только поиск для других устройств; по умолчанию он выключен.

Коротко по установке и настройке — [SETUP.md](SETUP.md).

---

## Установка

Есть три способа. Выберите один.

| Способ | Когда подходит |
|---|---|
| [Windows без Docker](#windows-без-docker) | проще всего на Windows; работает браузерный режим с окном проверки |
| [Linux без Docker](#linux-без-docker) | проще всего на Linux; можно включить автозапуск через systemd |
| [Docker (Windows и Linux)](#docker-windows-и-linux) | изолированно, одинаково на обеих ОС; без окна для браузерного режима |

### Windows без Docker

1. Установите **Python 3.10 или новее** с https://www.python.org/downloads/.
   В первом окне установщика отметьте **«Add python.exe to PATH»**.
2. Распакуйте modelseek в любую папку, например `C:\Users\<имя>\modelseek`.
3. Дважды кликните **`start.bat`**. При первом запуске он:
   - создаст окружение `.venv` и поставит зависимости (нужен интернет, 1–2 минуты);
   - скопирует `.env.example` в `.env`;
   - запустит сервер и откроет http://127.0.0.1:8088.

   Окно консоли не закрывайте: это и есть работающий modelseek. Остановить — `Ctrl+C` или закрыть окно.
4. Дальше — [первая настройка](#первая-настройка).

Необязательно:

- **Дополнительные модули** (браузерный режим, смысловой поиск и др.) ставятся в интерфейсе:
  *Настройки → Компоненты*. Если из интерфейса не получается — запустите `install-extras.bat`.
- **Автозапуск при входе в Windows** (нужен, чтобы подписки проверялись сами): запустите `autostart.bat`.
  modelseek будет стартовать в фоне без окна, журнал — в `data\modelseek.log`. Отключить: `autostart.bat remove`.

### Linux без Docker

1. Поставьте Python 3.10+ и модуль venv:
   - Debian / Ubuntu: `sudo apt install python3 python3-venv`
   - Arch / CachyOS: `sudo pacman -S python`
   - Fedora: `sudo dnf install python3`
2. Распакуйте modelseek и запустите:

   ```bash
   cd modelseek
   chmod +x start.sh install-extras.sh install-service.sh
   ./start.sh
   ```

   Скрипт создаст `.venv`, поставит зависимости, скопирует `.env.example` в `.env` и откроет
   http://127.0.0.1:8088 (если есть `xdg-open`). Порт меняется так: `MODELSEEK_PORT=9000 ./start.sh`.
3. Дальше — [первая настройка](#первая-настройка).

Необязательно:

- **Дополнительные модули** — *Настройки → Компоненты* или `./install-extras.sh`.
  Для браузерного режима Chromium нужны системные библиотеки; скрипт подскажет команду для конкретного дистрибутива.
- **Автозапуск через systemd** (для подписок): `./install-service.sh`. Создаёт пользовательский сервис
  `modelseek.service`. Статус: `systemctl --user status modelseek`, логи: `journalctl --user -u modelseek -f`.
  Чтобы сервис работал и без входа в систему: `sudo loginctl enable-linger $USER`.

### Docker (Windows и Linux)

Контейнеры modelseek — Linux-контейнеры. На Linux они работают напрямую, на Windows — внутри
Docker Desktop (он поднимает лёгкую Linux-виртуалку через WSL 2). Поэтому образ и `docker-compose.yml`
одни и те же, а отличия только в установке Docker:

- **Windows:** установите [Docker Desktop](https://www.docker.com/products/docker-desktop/), при установке
  оставьте включённым WSL 2, перезагрузитесь и запустите Docker Desktop. Команды ниже — в PowerShell.
- **Linux:** установите Docker Engine и плагин Compose (`docker compose version` должен работать).
  Arch / CachyOS: `sudo pacman -S docker docker-compose && sudo systemctl enable --now docker`,
  затем `sudo usermod -aG docker $USER` и перелогиньтесь.

Запуск (одинаково на обеих ОС, из папки modelseek):

```bash
docker compose up -d --build
```

Откройте http://127.0.0.1:8088. Данные (избранное, подписки, настройки, ключи) хранятся в томе Docker —
см. «Данные и ключи» ниже.

Дополнительно:

| Что | Команда |
|---|---|
| Свой SearXNG для «любых сайтов» | `docker compose --profile web up -d` |
| Ollama для перевода запросов | `docker compose --profile ollama up -d`, затем *Настройки → Перевод и смысл → Скачать модель* |
| Облегчённый образ без curl_cffi, fastembed, Pillow | `MODELSEEK_EXTRAS=0 docker compose build` (PowerShell: `$env:MODELSEEK_EXTRAS=0; docker compose build`) |
| Другой порт | переменная `MODELSEEK_PORT=9000` или строка `MODELSEEK_PORT=9000` в файле `.env` рядом с compose |
| Открыть с других устройств | включите [внешний профиль](#доступ-с-других-устройств) в `config.yaml`; порт на компьютере — `MODELSEEK_PUBLIC_PORT` (8090) |
| Логи | `docker compose logs -f modelseek` |
| Остановить | `docker compose down` (данные останутся; `down -v` удалит и их) |
| Резервная копия данных | `docker compose cp modelseek:/app/data ./modelseek-backup` (в копии лежат ключи — не выкладывайте её) |
| Восстановить из копии | `docker compose cp ./modelseek-backup/. modelseek:/app/data`, затем<br>`docker compose exec -u root modelseek sh -c "chown -R modelseek: /app/data; chmod 600 /app/data/secrets.env"`<br>и `docker compose restart modelseek` |

Чем Docker отличается от запуска без него:

- **Данные и ключи** лежат в томе `modelseek_modelseek-data`, а не в папке `data/`. Том сохраняется при
  `docker compose up -d --build`, `docker compose down` и перезапуске Docker Desktop. Стирают его
  `docker compose down -v`, удаление тома в Docker Desktop (*Volumes → Delete*) и *Troubleshoot → Clean / Purge data*.
  Ключи из `.env` рядом с `docker-compose.yml` от тома не зависят, и значение из `.env` важнее сохранённого
  в интерфейсе.
- **Браузерный режим** (`mode: browser`) в контейнере не работает: окно для прохождения проверки
  открыть негде. Режим `impersonate` работает.
- **Компоненты** curl_cffi, fastembed и Pillow входят в образ (кроме сборки с `MODELSEEK_EXTRAS=0`).
  Playwright в образ не входит, потому что браузерный режим в контейнере не работает.
- **Ollama на самом компьютере** (не в контейнере): в *Настройки → Перевод и смысл* укажите адрес
  `http://host.docker.internal:11434/v1`. На Linux Ollama должна слушать не только localhost:
  `OLLAMA_HOST=0.0.0.0` в её настройках.
- **На Windows** держите папку modelseek на диске Windows или внутри WSL — обе работают; `config.yaml`
  подключается в контейнер только для чтения.

### Первая настройка

1. Откройте http://127.0.0.1:8088 и сделайте пробный поиск, например `gridfinity`.
   Сразу работают Printables, а MakerWorld и Thangs появляются ссылками в строке «Искать также на…».
2. **Ключи API** (бесплатные) — *Настройки → Источники*, поле «Токен» / «API-ключ» у каждого сайта:
   - Thingiverse: https://www.thingiverse.com/apps/create → Desktop app → App Token
   - Cults3D: https://cults3d.com/en/api/keys (логин — ник на Cults3D)
   - MyMiniFactory: https://www.myminifactory.com/settings/developer
3. По желанию — карточки с MakerWorld и Thangs: *Настройки → Компоненты → playwright* (или curl_cffi),
   затем *Настройки → Источники → режим `browser`* (или `impersonate`). См. [режимы](#режимы-источников).
4. По желанию — тема в *Настройки → Внешний вид*.

### Обновление

- Без Docker: замените файлы новой версией, папки `.venv` и `data` оставьте. Запустите `start.bat` / `./start.sh` —
  он доставит новые зависимости.
- Docker: замените файлы и выполните `docker compose up -d --build`.

`config.yaml` в новой версии может измениться. Изменения из интерфейса лежат отдельно
(`data/settings.yaml`) и при обновлении сохраняются.

### Если что-то не работает

| Симптом | Что сделать |
|---|---|
| `start.bat`: «Python 3.10+ not found» | переустановите Python с галочкой «Add python.exe to PATH» |
| `start.sh`: не создаётся `.venv` | Debian/Ubuntu: `sudo apt install python3-venv` |
| Порт 8088 занят | `MODELSEEK_PORT=9000` перед запуском |
| Чип источника «ошибка» | наведите на него курсор — там причина; если «доступ запрещён» — нужен ключ или режим `browser` |
| Чип «пауза» | источник трижды подряд ответил ошибкой и отдыхает 10 минут; кнопка ↻ включает его сразу |
| Режим browser: «не установлен playwright» | *Настройки → Компоненты* или `install-extras` |
| Docker на Windows: `docker: command not found` | запустите Docker Desktop и откройте новый терминал |

## Что умеет

### Режимы источников

| Режим | Что делает |
|---|---|
| `http` | обычные запросы; для официальных API (Thingiverse, Cults3D, MyMiniFactory) и Printables |
| `link` | сайт не опрашивается, в строке «Искать также на…» появляется ссылка; **по умолчанию для MakerWorld и Thangs** |
| `impersonate` | запрос с TLS-отпечатком Chrome (модуль curl_cffi) |
| `browser` | настоящий Chromium (модуль playwright); при проверке на бота появляется кнопка «Пройти проверку» — откроется окно, проходите сами |

`impersonate` и `browser` обходят защиту сайтов от ботов, а это обычно против их правил. Это личный
инструмент: делайте немного запросов и не используйте его для массового сбора данных.

### Поиск по картинке

Кнопка с камерой у строки поиска. Картинку (файл, перетаскивание, вставка из буфера или ссылка) ищут
сервисы, которые это умеют: **Google Lens, Яндекс Картинки, Bing Visual Search**. Картинка уходит напрямую
в выбранный сервис и открывается у него в новой вкладке; modelseek её не сохраняет. Большие фото перед
отправкой уменьшаются до 1600 px.

У каждой карточки есть кнопка «Похожие по картинке» — тот же поиск по её превью.

Для 3D-файлов (STL, 3MF) поиск по форме умеет Thangs — диалог даёт ссылку.

### Смысловой поиск (дополнительный модуль)

Не входит в базовую установку. Локальная мультиязычная модель (~220 МБ, работает на процессоре)
добавляет в рейтинг сигнал «смысловая близость»: «держатель наушников» ≈ «headphone holder».
Включается в *Настройки → Перевод и смысл* после установки модуля fastembed.

### Перевод запросов

Русские запросы переводятся на английский через любой OpenAI-совместимый API: Ollama, LM Studio, облако.
В *Настройки → Перевод и смысл* Ollama ставится (Windows — winget, macOS — brew), запускается и
скачивает модель кнопками. На Linux установщик Ollama требует `sudo`, поэтому интерфейс показывает команду.

### Рейтинг

```
score = Σ вес_сигнала · сигнал  ×  вес_источника
```

| Сигнал | Что значит |
|---|---|
| Совпадение слов | доля слов запроса в названии (со словоформами) и тегах + нечёткое сходство |
| Смысловая близость | только с модулем fastembed |
| Позиция на сайте | собственный поиск сайта тоже что-то знает |
| Популярность | `log(лайки + 0.3·скачивания + 3·makes)`, нормированная внутри каждого сайта |
| Свежесть | экспоненциальное затухание с периодом полураспада |
| Похоже на избранное | авторы и теги из избранного |

Недоступные сигналы исключаются, остальные веса перенормируются. Нажмите на балл в карточке — увидите разбивку.

**Темы над выдачей:** для «hornet» это «hollow knight», «super hornet», «hornet trap». Клик оставляет одну тему, «−» исключает.

**Склейка дублей:** одна модель на разных сайтах показывается одной карточкой со ссылками «+ Thingiverse».

### Фильтры и пресеты

Цена (бесплатно / платно / до N €), минимум лайков, скачиваний и печатей, период публикации, лицензия
(можно ли продавать печать), обязательные и исключённые слова, скрытые авторы, только с превью,
скрыть уже открытые. Встроенные пресеты: «Проверенные», «Свежие (30 дней)», «Бесплатные и популярные»,
«Можно продавать печать», «Без мусора», «Новое для меня»; текущие фильтры можно сохранить как свой.

### Избранное, подписки, уведомления

- ♡ на карточке — в коллекцию; во вкладке «Избранное» — коллекции и заметки.
- «Подписаться» сохраняет запрос с фильтрами. Периодичность: от каждого часа до раза в неделю или своё
  число минут. Первый успешный ответ каждого сайта запоминается как начальная выдача, дальше видны только новые
  модели. Если сайт был недоступен, его модели не считаются новыми, когда он вернётся. Там, где сайт умеет
  сортировать сам, подписка спрашивает самые новые модели.
  Проверки идут, пока modelseek запущен (см. автозапуск).
- Уведомления: ntfy, Telegram или webhook — *Настройки → Подписки и уведомления*.

### Свои источники

*Настройки → Свои источники → Добавить источник*: адрес API с подстановками `{q}`, `{limit}`, `{offset}`,
`{page}`, `{page0}`, метод GET или POST, путь к массиву моделей и поля. «Проверить» показывает массивы
в ответе, поля первого элемента (назначаются кликом) и превью карточек. Там же — сайты-ссылки для
строки «Искать также на…».

## Доступ с других устройств

Админский профиль всегда открывается только с этого компьютера: он слушает `127.0.0.1` и отклоняет запросы
с других адресов и через прокси. Для телефона, ноутбука или друзей есть **внешний профиль** — отдельный порт
в том же процессе, с общим кэшем и теми же источниками.

Что есть во внешнем профиле: поиск, фильтры, веса, темы, своё избранное и пресеты. Всё это хранится в
браузере гостя: настройки поиска и тема — в куки, избранное, история и скрытые модели — в его хранилище.
Чего нет: избранного, истории, подписок и ключей владельца, установки компонентов, настроек сервера. Таких
адресов на внешнем порту не существует вовсе. Запросы гостей не попадают в историю владельца.

Включается в `config.yaml` (через интерфейс нельзя) и требует перезапуска:

```yaml
public:
  enabled: true
  port: 8090
  auth: password          # none | password | subnet
  allow_from: []          # например [192.168.1.0/24]; для auth: subnet обязательно
```

| `auth` | Кто попадёт |
|---|---|
| `none` | все, кто дотянется до порта (с учётом `allow_from`) |
| `password` | знающие общий пароль. Пароль задаётся в *Настройки → Сервер → Внешний профиль* или переменной `MODELSEEK_PUBLIC_PASSWORD`; смена пароля выводит всех гостей |
| `subnet` | только адреса из `allow_from` |

Ещё есть ограничение поисков в минуту с одного адреса (`searches_per_minute`), одновременных поисков
(`max_parallel_searches`) и список источников для гостей (`sources`). Свои источники владельца в локальной сети
гостям не показываются. Пять неверных паролей подряд закрывают вход с этого адреса на 10 минут.

**Гость ищет от своего имени.** Ключи API владельца гостям не выдаются. Гость вводит свои в *Настройки → Ключи
сайтов*: они хранятся в куки его браузера и приходят на сервер только вместе с его поиском. Без ключа такой
сайт для гостя пропускается; `public.lend_keys: true` разрешает искать с ключом владельца тем, у кого своего нет.
Ошибки с ключом гостя не ставят источник на паузу в админском профиле.

Сайты, которые отвечают скриптам с чужих страниц (CORS), браузер гостя опрашивает сам, со своим ключом и со
своего адреса; сервер только разбирает и ранжирует ответ. Такой ответ идёт только этому гостю и не попадает
в кэш, а ссылки из него проверяются, как любые другие. Из встроенных источников так умеет MyMiniFactory. Printables,
Thingiverse и Cults3D запросы из браузера запрещают — их гостевые поиски идут через сервер. Если сайт не ответил
браузеру, поиск тоже пойдёт через сервер.

Внешний порт рассчитан на недоверенных посетителей: тело запроса не больше 4 КБ, заголовки не больше 16 КБ,
запрос должен прийти целиком за 10 секунд, с одного адреса — не больше 24 соединений. Поэтому медленные
и «висящие» соединения не забивают сервер, а админский профиль продолжает отвечать.

Через интернет открывайте внешний профиль только за reverse proxy с HTTPS: пароль и ключи гостя по обычному
HTTP идут открытым текстом. Адрес прокси укажите в `public.trusted_proxies`, чтобы лимиты считались по
настоящему IP гостя.

**В Docker** внешний порт по умолчанию открыт только на этом компьютере. Чтобы пустить другие устройства,
добавьте в `.env` строку `MODELSEEK_PUBLIC_BIND=0.0.0.0` и выполните `docker compose up -d`. Docker Desktop
передаёт контейнеру всех гостей с одного адреса — своего шлюза. Поэтому лимиты там считаются по браузеру
(у каждого гостя случайный номер в куки), а для тех, кто куки сбрасывает, есть общий потолок. `allow_from`
и `auth: subnet` в Docker Desktop гостей не пропустят: их настоящие адреса не видны. Нужна проверка по
адресам — запускайте modelseek без Docker.

## Конфигурация

Слои, каждый следующий перекрывает предыдущий:

1. значения по умолчанию в коде;
2. `config.yaml` — правится руками;
3. переменные окружения `MODELSEEK__РАЗДЕЛ__КЛЮЧ` (например, `MODELSEEK__TRANSLATE__URL`) — так Docker
   подставляет адреса сервисов;
4. `data/settings.yaml` — всё, что изменено в интерфейсе. Значение `null` удаляет ключ из `config.yaml`.

Ключи API лежат в переменных окружения: `.env` (читают `start.bat`, `start.sh`, Docker) или
`data/secrets.env` (его пишет интерфейс). В `config.yaml` указываются только **имена** переменных.

### Справочник `config.yaml`

## Для разработки

На Windows вместо `. .venv/bin/activate` — `.venv\Scripts\activate`.

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
python -m app.serve                         # оба профиля, как в скриптах запуска
uvicorn app.main:app --reload --port 8088   # только админский, с перезагрузкой при правках
```

Новый встроенный источник — класс в `app/sources/` с методом `search(fetcher, query, limit, page)`,
строчка в `REGISTRY` (`app/sources/__init__.py`) и секция в `config.yaml`. `fetcher` выбирается по `mode`,
поэтому новый источник сразу работает во всех режимах. Если сайт умеет сортировать сам, задайте `native_sorts`
(сортировка modelseek → значение сайта) и примите в `search` аргумент `sort`.

API: `GET /api/search/stream?q=…` (SSE), `GET /api/search`, `/api/sources`, `/api/settings`,
`/api/favorites`, `/api/subs`, `/api/presets`, `/api/history`, `/api/extras`, `/api/ollama`, `/api/jobs/{id}`.
Изменяющие запросы принимаются только с заголовком `X-Modelseek: 1`.

## Безопасность

Админский профиль слушает только `127.0.0.1` и отвечает только этому компьютеру (запросы с других адресов
и через прокси отклоняются). В Docker порт публикуется только на `127.0.0.1` компьютера, а контейнер
отвечает только шлюзу Docker: соседние контейнеры в той же сети получают отказ. В нём есть установка
программ и запись ключей, поэтому:

- запросы принимаются только на разрешённые адреса (`server.allowed_hosts`), это закрывает DNS rebinding;
- API не отвечает на запросы с других сайтов, а изменяющие запросы проверяют `Origin`;
- путь к браузеру, `allowed_hosts` и `data_dir` нельзя поменять через API;
- токен перевода и уведомлений из интерфейса нельзя взять из ключа сайта или системной переменной — только
  из ключей, сохранённых в настройках или в `.env`; в `config.yaml` имя переменной задаётся без этой проверки;
- изменяющие запросы требуют заголовок `X-Modelseek: 1`, который чужая страница в браузере отправить не может.

Для доступа с других устройств есть [внешний профиль](#доступ-с-других-устройств): в нём нет ни одного адреса,
который меняет настройки или читает данные владельца.

### Защита от сайтов, на которых идёт поиск

Ответы сайтов считаются недоверенными. Что бы ни вернул сайт, modelseek:

- не ходит во внутреннюю сеть (роутер, NAS, `169.254.169.254`, сам modelseek) — ни по редиректу, ни за превью,
  ни из страницы в режиме browser. Адрес проверяется после DNS, поэтому не помогают и имена вроде `evil.test → 127.0.0.1`;
- обращается к локальным адресам только там, где они указаны в настройках: SearXNG, Ollama, адрес уведомлений,
  свой источник. Чужой сайт не может перенаправить запрос даже на них;
- не передаёт ключи и заголовки источника другому сайту при редиректе и проходит не больше 5 перенаправлений;
- читает не больше 8 МБ ответа (4 МБ для картинки при склейке дублей), в том числе после распаковки gzip,
  и не раскрывает картинки больше 40 Мп;
- приводит результаты к безопасному виду: только ссылки http(s), длина названия, автора и тегов ограничена,
  бесконечные и отрицательные числа отбрасываются, невидимые символы для подмены текста удаляются;
- отдаёт страницу со строгим CSP (скрипты только свои, запросы только к modelseek), `Referrer-Policy: no-referrer`
  и запретом встраивания в чужие страницы;
- в режиме browser блокирует скачивание файлов и service worker'ы, а WebRTC не раскрывает локальный адрес.

Превью моделей браузер загружает напрямую с сайтов, поэтому сайты видят его IP-адрес, как при обычном
заходе. Шрифты лежат в `frontend/fonts`, сторонние сервисы шрифтов не используются.

Шрифты интерфейса — Orrery Text, производный от Jost\*, и Orrery Gauge для логотипа и заголовков. Оба под
SIL Open Font License 1.1, текст лицензии в `frontend/fonts/OFL.txt`.
